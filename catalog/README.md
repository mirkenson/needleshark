## Данные и общий шаблон

`products.json` — единственный источник товарных данных. `render.py` записывает готовые статические HTML в `dist/catalog/`; JavaScript не нужен для чтения описаний, размеров и FAQ. Главная не перегенерируется. Зависимостей и сборщика нет.

После изменения данных запустить из корня репозитория:

```sh
python3 catalog/render.py
python3 -m unittest discover -s catalog -p 'test_*.py'
python3 server/preview.py --port 4173
```

По умолчанию локальный просмотр не отправляет заявки. Для проверки действующей цепочки использовать `--live-api` и явно помеченные тестовые данные. В этом режиме форма действительно сохраняет заявку на VPS, в Google Sheets и отправляет уведомление.

- `order`: меньшее число ставит карточку выше.
- `visible: false`: убирает карточку из каталога, сохраняя товарную страницу и адрес.
- `seasonalNote`: пояснение временной недоступности на странице. Не оставлять покупателю ложное впечатление доступности: при сезонной паузе проверить и ссылки на площадки.
- `slug`: постоянный адрес. Для сезонного скрытия его не менять и запись не удалять.
- `sizes`: размеры в сантиметрах, в порядке владельца. Для этого прототипа приняты длина × ширина × высота по схеме исходной карточки 220 × 98 × 106.
- `sizeGuidance`: необязательные подсказки под размерами: `size`, `label`, `note`. Сопоставляются по тройке габаритов. Тип техники — приблизительный ориентир; марки и модели добавлять только при подтверждённой совместимости.
- `fastenings`: необязательные детали конструкции в блоке материала: `title`, `text`. У квадроцикла — резинка по низу и стяжка с фастексом, подтверждённые владельцем.
- `marketplaces`: название и `url`. `null` создаёт отключённую кнопку «Пока недоступно» без внешнего перехода. HTTPS-адрес создаёт внешний переход с `noopener noreferrer`. Привязку разных размеров к разным карточкам площадок согласовать отдельно.
- `images`: общий список изображений с уникальными `id`; первая фотография используется в карточке каталога. Состав галереи и фотографии разделов задаёт `galleries` (см. ниже). Старые роли `hero`, `fit`, `material` остаются запасным вариантом для товаров без `galleries`.
- `copy`, `scenarios`, `faq`, `kit`, `materialText`, `fitNote`: содержание страницы. Продуктовые тексты вынесены из шаблона.
- `sections`: включённые блоки и их порядок. Оглавление и нумерация следуют этому списку. Смысловая основа: применение → материал → размер → комплект → вопросы → B2B. При отключении блока его данные пока сохраняются в записи.

Владелец одобрил структуру 10 сентября 2026 года. Следующие товары добавлять в этом же формате через общий шаблон: первый экран и покупка → сценарии → материал и конструкция → подбор размера → комплект → вопросы → обращение за партией. Содержание и нужные блоки могут различаться, но смысловой порядок и общий стиль сохраняются. Не создавать отдельную независимую вёрстку для каждого изделия.

Чтобы добавить следующий товар, скопировать запись, задать новый `slug`, содержание, фото, размеры и ссылки; выполнить генерацию и визуальную проверку. Для новых систем размеров используются `variants`, `sizeLabel` и `measurementLabel`; три габарита остаются форматом прежнего товара без вариантов.

## Что делает форма сейчас

### Размеры, комплектации и цвета (14 сентября 2026)

Моточехол и чехлы для колёс добавлены через тот же шаблон. Сверка источников и расхождения: `docs/catalog-ozon-20260914.md`.

- `optionGroups`: группы выбора в порядке зависимости: комплектация, затем цвет (если есть), затем размер. У каждой группы `id`, `label`, список `values` с `id`, `label` и необязательным `note`. Цветовые варианты добавляются только по данным источника; у чехла коляски есть шесть подтверждённых цветов.
- `variants`: только реальные сочетания. `options` сопоставляет ID каждой группы выбранному ID значения; `id` уникален, `ozonUrl` ведёт на конкретный вариант, `galleryId` выбирает галерею комплектации, `kit` задаёт состав, `unitsPerPack` — число изделий в комплекте. Первый вариант выбран по умолчанию.
- `sizeLabel`: полная подпись размера с единицей. `legacySize`: Д × Ш × В для действующего серверного поля или пустая строка для других систем размеров. `rangeLabel` задаёт краткую подпись в каталоге; `measurementLabel` — подпись замера; `seoTitle` позволяет не выводить неподходящее «0 размеров».
- Переключение комплектации сохраняет размер, если он существует, иначе выбирает ближайшее сочетание по совпадающим опциям. Нижестоящие недоступные значения отключены. Таблица содержит все реальные сочетания и позволяет выбрать вариант целиком.
- Выбор обновляет Ozon URL, галерею и фотографии деталей на странице, список комплекта и контекст заявки. Для будущего цвета добавить группу и только существующие сочетания; отдельный шаблон/новый JavaScript не нужен.
- `site_utils.external_url` размечает также динамические ссылки. Для каждого Ozon URL обязательна одна `utm_campaign=vendor_org_211216`; не заменять её общей campaign сайта.
- Для новых вариантов все детали выбора передаются через существующий текст `question` в CRM/очередь/Google. Для колёс `quantity` — число чехлов, в интерфейсе — количество выбранных комплектов; количество комплектов также записывается в комментарий. Новый backend или миграция не нужны.

Кнопки открывают диалог с названием изделия, выбранным размером и типом обращения. Проверяются обязательные поля, email/телефон, целое положительное количество и чекбокс. `dist/catalog.js` отправляет запрос на существующий `/api/leads`; успех показывается только после подтверждения сохранения в PostgreSQL и очереди SQLite. На время запроса поля блокируются. После потери ответа повтор с тем же содержанием использует тот же UUID.

Поля `product_slug`, `product_name`, `product_size`, `inquiry_type`, `quantity`, `source_path` хранятся в отдельных nullable-колонках `orders`. В Google Sheets и письме они включаются в существующий текст «Задача». Файл в товарной форме не предусмотрен. Действующий `dist/script.js` главной не меняется. Установка и модель данных: `server/README.md`, `docs/DATABASE.md`.

## Галереи комплектаций и детали (14 сентября 2026)

- `galleries` сопоставляет ID галереи её данным: `label`, упорядоченные ID `images`, фото `hero`, `material`, `fit`, `kit`, текст `materialText`, подпись `materialCaption` и карточки деталей `features` (`image`, `title`, `text`). Все фотографии разделов и деталей должны входить в выбранную галерею; `hero` — её первый кадр. Валидатор останавливает генерацию при нарушении этих условий.
- `variants[].galleryId` связывает реальное сочетание опций с галереей. Для товара без вариантов используется `defaultGallery`. Будущий цвет может иметь отдельную галерею в той же модели данных.
- Общие детали допустимо использовать в нескольких галереях, если конструкция совпадает. Общий вид другой модели и её особые детали в соседнюю комплектацию не входят. У обычного моточехла нет снимков вставки, вентиляции или светоотражателей; комплекты колёс различаются общим видом и количеством, сохраняя одинаковые детали одного чехла.
- Начальный HTML показывает только выбранную по умолчанию галерею. При переключении комплектации меняются миниатюры, основной кадр, материал, фото подбора размера и комплекта, карточки деталей и подписи. Шаблоны других наборов остаются инертными. Изменение только размера сохраняет текущий кадр. Миниатюры работают с клавиатуры.
- В каталоге и на всех трёх страницах есть отключённые Wildberries и Яндекс Маркет; ссылок на них пока нет.
- FAQ отвечает на вопросы о посадке, комплектации, водостойкости, прочности, производстве и прямом заказе. По ответу владельца доставку при прямом заказе согласуем индивидуально; службы, сроки и стоимость заранее не обещаем.
- 14 новых изображений деталей созданы встроенным ImageGen по исходным материалам. Промпты и происхождение: `docs/assets/catalog-detail-image-prompts.json`. Это визуализации; они не подтверждают экспериментально водостойкость, прочность или допустимую температуру.
