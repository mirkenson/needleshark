# Прототип каталога Needle Shark

Локальные страницы: `/catalog/` и `/catalog/chehol-na-kvadrocikl/`.
Главная, действующая форма, аналитика, VPS и Sites preview не изменены.
Верхняя плашка и `noindex,nofollow` обозначают прототип. Публикация владельцем пока не запрошена.

## Данные и общий шаблон

`products.json` — единственный источник товарных данных. `render.py` записывает готовые статические HTML в `dist/catalog/`; JavaScript не нужен для чтения описаний, размеров и FAQ. Главная не перегенерируется. Зависимостей и сборщика нет.

После изменения данных запустить из корня репозитория:

```sh
python3 catalog/render.py
python3 -m unittest discover -s catalog -p 'test_*.py'
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

- `order`: меньшее число ставит карточку выше.
- `visible: false`: убирает карточку из каталога, сохраняя товарную страницу и адрес.
- `seasonalNote`: пояснение временной недоступности на странице. Не оставлять покупателю ложное впечатление доступности: при сезонной паузе проверить и ссылки на площадки.
- `slug`: постоянный адрес. Для сезонного скрытия его не менять и запись не удалять.
- `sizes`: размеры в сантиметрах, в порядке владельца. Для этого прототипа приняты длина × ширина × высота по схеме исходной карточки 220 × 98 × 106.
- `marketplaces`: название и `url`. `null` создаёт кнопку с пояснением о заглушке. HTTPS-адрес создаёт внешний переход с `noopener noreferrer`. Привязку разных размеров к разным карточкам площадок согласовать отдельно.
- `images`: галерея; первая фотография используется в карточке и первом экране. Роли `hero`, `fit`, `material` задают фото для остальных блоков; без роли используется первая фотография.
- `copy`, `scenarios`, `faq`, `kit`, `materialText`, `fitNote`: содержание страницы. Продуктовые тексты вынесены из шаблона.
- `sections`: включённые блоки и их порядок. Оглавление и нумерация следуют этому списку. Смысловая основа: применение → материал → размер → комплект → вопросы → B2B. При отключении блока его данные пока сохраняются в записи.

Чтобы добавить следующий товар, скопировать запись, задать новый `slug`, содержание, фото, размеры и ссылки; выполнить генерацию и визуальную проверку. Текущий размерный блок рассчитан на изделия с тремя габаритами. Иные системы размеров потребуется добавить при появлении конкретного товара.

## Что делает форма сейчас

Кнопки открывают диалог с названием изделия, выбранным размером и типом обращения. Проверяются обязательные поля, email/телефон, количество и чекбокс. Отправка демонстрационная: сетевых запросов и сохранения данных нет, вместо успеха показано пояснение. Файл в этой форме не предусмотрен. Действующий `dist/script.js` не подключается и не меняется.

## Перед публикацией после правок владельца

1. Согласовать соответствие обработанных фото реальному чехлу, тексты, размеры и порядок Д × Ш × В; цену пока не указывали.
2. Вставить действительные товарные ссылки Ozon, Wildberries и Яндекс Маркета, уточнить выбор размеров на каждой площадке.
3. Подключить товарную заявку к действующему серверу с передачей товара, размера, типа обращения и количества; проверить приём и доставку по правилам репозитория. Убрать демонстрационное поведение только вместе с рабочей интеграцией.
4. Добавить события аналитики для товара/размера/площадки без передачи контактов, проверить цели.
5. Завершить SEO-подготовку: согласованные запросы и тексты, canonical, структурированные данные по фактическим сведениям, карта сайта. Индексацию согласовать отдельно: сейчас её ограничивает также конфигурация VPS.
6. Убрать прототипные плашки и заглушки только из подготовленной к публикации версии. Проверить адаптив, сохранить проверенный коммит, отправить в GitHub, затем публиковать через `ops/deploy.sh`.

Обработка изображений: встроенный ImageGen по трём предоставленным владельцем изображениям. Итоговые JPG — `dist/catalog-assets/`. Точные промпты, исходные и сгенерированные пути — `docs/assets/atv-image-prompts.json`. Это визуализации для согласования; результат генерации не доказывает свойства материала или точность конструкции.
