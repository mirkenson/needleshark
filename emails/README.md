# Письма Needle Shark

## Состояние на 16 октября 2026

По прямому поручению владельца согласованный макет **«Получили ваше обращение — Needle Shark»** перенесён и сохранён в Unisender как HTML-шаблон **«Needle Shark — Получили ваше обращение»**. Он находится в «Рассылки → Мои шаблоны» (ID `7854042`, доступ только владельцу). Сохранение подтверждено появлением в списке и повторным открытием просмотра. Это шаблон: рассылка и автоматические сценарии не созданы, тестовых и клиентских отправок не было. DNS, почта, сайт, очередь и Битрикс24 не менялись; остальная автоматизация отложена до внедрения CRM.

Основа дизайна — [руководство по бренду](../docs/BRAND_GUIDE.md) и действующие стили сайта. Текст содержит добавленное владельцем уточнение «предпочтения в материале»; не менять его автоматически при переносе.

По уточнению владельца в шапку добавлены подпись «Швейное производство» и ссылка https://needle-shark.ru/. На широком экране они справа от логотипа, на узком — под ним. Основной текст письма прежний. [Проверка шапки](../docs/verification/20261016-email-header.json).

## Файлы

- `received.html` — сам макет письма: табличная вёрстка, основные стили inline, текст, ссылка на сайт и ссылка на email. Нет JavaScript, формы или аналитики.
- `received-unisender.html` — фактически импортированный HTML с публичным PNG в хранилище Unisender и Manrope с `fonts.gstatic.com`; локальных путей нет. Редактор Unisender может нормализовать HTML после загрузки.
- `received.txt` — исходный текст с темой, для сверки и будущей текстовой части MIME-письма. При формировании MIME первую строку вынести в Subject.
- `assets/needle-shark-logo.png` — точный растровый экспорт `dist/logo.svg`, 513 × 174 px, подложка `#F6F7F4`, показ в 171 × 58 px.
- `preview.html`, `preview.css`, `preview.js` — локальная оболочка согласования: компьютер/телефон, Manrope/Arial. Она показывает тот же `received.html` в iframe, не дублирует содержание.
- `previews/received-desktop.png`, `previews/received-mobile.png` — браузерные снимки макета.

## Локальный просмотр

Из корня репозитория:

```sh
python3 -m http.server 4216 --bind 127.0.0.1
```

Открыть http://127.0.0.1:4216/emails/preview.html или непосредственно http://127.0.0.1:4216/emails/received.html. Если порт занят другим сервером, выбрать свободный. Ссылка `mailto:` проверяется по адресу и доступности с клавиатуры; отправлять письмо для просмотра не требуется.

Файлы находятся вне `dist/`; штатная публикация сайта их не включает. Макеты помечены `noindex,nofollow`. Метрика, UTM, SEO-метаданные публичных страниц и подключения CRM здесь не нужны. Веб-предпросмотр не считается реальной отправкой или проверкой доставки.

## Перенос в Unisender выполнен

Использован HTML-редактор: «Загрузка из файла», затем «Сохранить и выйти». Тема задана отдельно: `Получили ваше обращение — Needle Shark`. PNG загружен с архивом; итоговый `received-unisender.html` содержит фактический HTTPS-адрес картинки. Manrope подключён напрямую с официального CDN Google Fonts: оба WOFF2 побайтово совпали со шрифтами сайта и возвращают HTTP 200 с разрешённой междоменной загрузкой. Arial и MSO-fallback сохранены. Архивный импорт Unisender не переписывает URL шрифтов, поэтому не использовать в письме локальные `fonts/...` или адреса сайта без CORS.

Текст и композиция совпадают с согласованным макетом: изменены только URL ресурсов, убран favicon локального просмотра. Проверены обычный и мобильный предпросмотр сервиса, включая конец письма, обе ссылки и автоматически созданная текстовая версия. Шаблон повторно открыт из списка после сохранения. Предпросмотр Unisender не заменяет настоящие почтовые клиенты; прежние проверки пяти ширин относятся к локальному макету. [Отчёт переноса](../docs/verification/20261016-unisender-import.json).

Для повторного импорта использовать `received-unisender.html`; `received.html` оставлен локальным эталоном. Оболочка просмотра и её JavaScript в Unisender не переносятся.

Отправитель по макету — Needle Shark, рабочий адрес — info@neesha.ru. Реальные From/Reply-To/аутентификация ещё не настроены. Фраза «в ответ на это письмо» требует проверки маршрута ответа в рабочую почту и будущую CRM.

После переноса нужны тестовые отправки в реальные почтовые клиенты, проверка светлой/тёмной темы, заблокированных изображений, ответа и фактической доставки. Автоматическую цепочку не включать в рамках подготовки макета.

Первоначальная проверка макета: [обезличенный отчёт](../docs/verification/20261016-email-brand-preview.json).
