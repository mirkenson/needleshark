## Добавление материала из диктовки

1. Получить тему и факты от владельца, оформить связный текст. Не добавлять неподтверждённые свойства, цифры, отзывы и авторство. Вопросы о недостающих фактах решать до публикации.
2. Добавить запись в `posts.json` со статусом `draft`. Текст разбить на абзацы, смысловые подзаголовки и списки. Сначала показать владельцу текст; публикация на VPS — отдельный этап.
3. После согласования поставить `published`, указать фактическую дату публикации, запустить генератор, проверить страницу и навигацию в браузере. Сохранить проверенную версию в GitHub перед публикацией через `ops/deploy.sh`.

Формат записи (пример структуры, не готовая публикация):

```json
{
  "slug": "tema-stati",
  "status": "draft",
  "date": "2026-09-11",
  "title": "Согласованный заголовок",
  "description": "Краткое введение для списка и начала статьи.",
  "blocks": [
    {"type": "paragraph", "text": "Текст абзаца."},
    {"type": "heading", "text": "Подзаголовок"},
    {"type": "list", "items": ["Первый пункт", "Второй пункт"]}
  ]
}
```

`slug` уникален, содержит латинские строчные буквы, цифры и дефисы; опубликованный адрес сохранять. `date` — ISO-дата. Сортировка по дате, новые сверху. Разметка HTML в тексте экранируется. Черновики не создают публичных файлов. При переводе опубликованного материала в draft генератор удаляет только ранее созданную им страницу: не делать этого без явного решения о снятии публикации. `dist/blog/` вручную не редактировать. Новые типы блоков добавлять в общем генераторе по необходимости.

## Статья для поиска и целевого действия

Для каждого материала определить вопрос читателя, связь с производством/товаром и уместные целевые действия. `description` — короткий самостоятельный ответ/введение, а не набор ключей. Один H1 создаётся из `title`, смысловые H2 — блоками `heading`; список — `list`. Использовать естественные названия изделий, материалов, задач и синонимы по смыслу; без переспама, скрытых ключей и обещаний позиций в поиске/ответах AI. Факты, условия эксплуатации и совместимость проверять у владельца. Не выдавать предположения за опыт производства.

Между смысловыми разделами разместить небольшой блок `cta`: сначала естественная подводка от предыдущего текста, затем предложение полезного следующего шага. Не вставлять одинаковую рекламу после каждого абзаца. Для каждой будущей статьи выбрать покупку/подбор товара, переход на подтверждённый маркетплейс или подписку на реальный канал. Если адрес пока неизвестен, оставить материал черновиком и уточнить ссылку, не ставить заглушку.

```json
{
  "type": "cta",
  "id": "catalog-selection",
  "lead": "Подводка, связанная с предыдущим разделом",
  "text": "Короткое предложение следующего шага без неподтверждённых обещаний.",
  "label": "Посмотреть изделия",
  "url": "/catalog/"
}
```

`id` — постоянный идентификатор CTA внутри статьи, строчные латинские буквы/цифры/дефисы. Не менять при правке подписи. `url` — существующий внутренний путь или проверенный HTTPS-адрес; внешние ссылки открываются в той же вкладке. Не передавать личные данные через URL. Событие Метрики `blog_cta_click` содержит только slug статьи, id CTA и путь страницы. В кабинете счётчика 112428810 цель `blog_cta_click` создана 11 сентября 2026, ID 611918849; новые CTA используют её автоматически.

Необязательные поля записи: `seoTitle`, `seoDescription` (если нужны отдельные метаданные), `author` (только настоящее согласованное имя человека), `updated` (реальная дата изменения YYYY-MM-DD, не раньше публикации). По умолчанию title/meta description берутся из заголовка и введения. Canonical автоматически указывает на основной HTTPS-домен `needle-shark.ru`, включая просмотр через www. Open Graph и JSON-LD BlogPosting строятся из тех же реальных полей. Не добавляются выдуманные рейтинги, просмотры, авторы, изображения или товары.

FAQ добавлять только при наличии полезных вопросов по теме:

```json
{"type": "faq", "items": [{"question": "Реальный вопрос читателя", "answer": "Проверенный прямой ответ."}]}
```

Прежний блок FAQ выводится видимым текстом с H2/H3, без обещания расширенного результата поиска. Отдельная FAQPage-разметка не добавляется автоматически. Владелец разрешил включение индексации. После подготовки статических страниц запустить `python3 ops/prepare-public.py` для обновления sitemap/robots. Попадание в поиск и позиции не гарантируются.

Основа разметки: https://developers.google.com/search/docs/appearance/structured-data/article ; событие CTA: https://www.yandex.ru/support/metrica/ru/objects/reachgoal .

Для проверяемых материалов используйте блок `sources` сразу после относящегося к нему раздела: `{"type":"sources","items":[{"title":"Производитель: название руководства","url":"https://..."}]}`. Ссылки должны вести на прочитанные первичные источники. Советы для конкретной модели не обобщать на всю технику; ограничения источника, влияющие на выбор товара, сохранять рядом с CTA.

## Подача длинных статей (14 сентября 2026)

Редакционные блоки обрабатываются в `blog/blocks.py`; `blog/render.py` сохраняет общий шаблон и публикацию. Пример применения — статья о зимнем хранении. Фотографии берутся из существующих записей `catalog/products.json` и `ops/image-manifest.json`, отдельные копии файлов для блога не нужны.

- `heading` принимает необязательные `id` и `tocLabel`. Оглавление создаётся автоматически. ID превращается в `section-<id>`; сохраняйте его после публикации. Без ID используется позиционный `section-auto-N`.
- В тексте абзацев, списков, пояснений и подписей доступны `**смысловой акцент**` и `==выделение фоном==`. Остальной HTML экранируется. Используйте выделения выборочно, оставляя основной текст спокойным.
- `callout`: `title`, `text`, необязательный `tone` (`note` или `important`). Ключевой совет или ограничение товара остаётся видимым, без раскрытия.
- `image`: `product` — slug товара, `image` — ID изображения в товаре, `caption` — подпись. Alt, размеры и адаптивные WebP наследуются из каталога. Генератор отклоняет неизвестные товары/фотографии.
- `tabs`: необязательный постоянный `id`, `title`, `items` со свойствами `label` и `blocks`. Используйте для альтернативных сценариев, например места стоянки. В панелях допустимы `paragraph`, `list`, `sources`. Без JS видны все панели с заголовками; с JS работают клики, стрелки влево/вправо, Home/End, Tab и роли WAI-ARIA.
- `accordion`: необязательный постоянный `id` и такая же структура `title`/`items`/`label`/`blocks`. Нативные `details`/`summary` подходят для дополнительных пояснений и примеров по отдельным моделям, а не для скрытия основных шагов. Работают без JS и с клавиатуры.
- `checklist`: необязательный постоянный `id`, `title` и текстовые `items`. Доступные чекбоксы и счётчик отмеченного. Отметки не сохраняются приложением после перезагрузки. В Метрику передаётся только номер пункта и состояние отметки, без текста.
- `sources`: прежний формат сохранён. В тексте появляются номера источников, в конце — список с обратными ссылками к каждому упоминанию. Повторные URL объединяются; первый заголовок используется в списке. JS раскрывает нужный аккордеон/таб при возврате из сноски. Вложенные источники включаются в `BlogPosting.citation`.
- `cta`: прежние `id`, `lead`, `text`, `label`, `url` сохранены. Необязательный `image` принимает объект с `product`/`image`/`caption`. Дополнительные ссылки задаются через `links: [{id, label, url}]`; ID всех CTA-ссылок внутри статьи уникальны. Каждая ссылка получает прежнее событие `blog_cta_click`; ссылки Ozon — `utm_campaign=vendor_org_211216` через общий `prepare_html`.

Для длинной статьи размещайте минимум два органичных CTA в разных смысловых частях; в текущей статье три блока и пять переходов в каталог/на Ozon. Подводка должна помогать следующему действию читателя. Технические ограничения хранения сохраняйте рядом с предложением товара. Фотографии изделий и деталей должны иллюстрировать соседний текст.

Основа редакционной подачи: [NN/g — Formatting Long-Form Content](https://www.nngroup.com/articles/formatting-long-form-content/), [W3C — Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). Проверены 14.09.2026. Бренд, шрифт, цвет и остальная структура сайта сохранены; новые размеры текста заданы в `dist/typography.css` только для компонентов блога.
