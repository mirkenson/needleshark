Это первый слой против простых автоматических отправок, без внешнего сервиса и без гарантии распознавания человека. Порядок включения и ограничения — в `server/README.md`; публикация и фактические проверки — в PROJECT_CONTEXT/отчёте выпуска.

## Сборка и просмотр

```sh
python3 b2b/render.py --publish
python3 ops/prepare-public.py
python3 ops/check-site.py
python3 server/preview.py --port 4191
```

`--publish` создаёт **dist**, но не устанавливает сайт на VPS. Локальный `server/preview.py` по умолчанию возвращает 503 для API и не создаёт заявки. Отдельный безопасный прототип: `python3 b2b/render.py` и `python3 b2b/preview.py --port 4190`; его `outputs/b2b-preview` имеет noindex, без SDK и отправки. Не публиковать preview.

## Выпуск и восстановление

Перед статикой установить добавляющую четыре nullable-поля миграцию и backend: `bash ops/install-server-mail.sh --upgrade`. Режим сохраняет SMTP/LOOP/env/systemd, делает закрытую резервную копию конфигурации и БД. Код должен быть закоммичен и отправлен в upstream.

Затем `bash ops/deploy.sh --from-github`, после успешного переключения `bash ops/install-b2b-redirects.sh`: ровно 78 старых адресов 26 товаров перенаправляются на `/catalog/#slug` с сохранением query. Установка редиректов сохраняет реальную конфигурацию Nginx, вставляет только include, проверяет nginx -t и откатывает при ошибке.

Исходники всех прежних страниц сохранены меткой `backup/site-before-b2b-20261008` (ff10106), каталог products.json и старые шаблоны не удалены. Отдельный архив — outputs/site-before-b2b-20261008.tar.gz в основном репозитории. VPS-релиз закреплён `rollback-before-b2b-20261008`. Перед восстановлением проверить текущие ссылки; переключить проверенный старый статический релиз и восстановить Nginx из закрытой копии до B2B. Новые колонки совместимы со старым backend и не требуют удаления. Не восстанавливать старый dump поверх новых заявок.

## Проверки

```sh
python3 -m unittest b2b.test_render
node --test b2b/test*.mjs ops/test_analytics.mjs
python3 -m unittest discover -s server -p 'test_*.py'
```

Серверный `check_delivery_postgres.py` выполняется только в отдельной временной схеме с CRM_TEST_DSN, без отправки сообщений. Проверяет транзакции, повторные UUID, очереди, обе пары контактов, новые поля и совместимость старых записей. Публичная цепочка и адаптив проверяются отдельно; результаты локальных заглушек не считаются подтверждением доставки или обработки Метрикой.
