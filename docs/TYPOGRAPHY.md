# Типографика и визуальная система Needle Shark

Обновлено 11 сентября 2026. Инструкция относится ко всем семи страницам и общим шаблонам каталога/блога. Изменения этого этапа подготовлены локально; факт публикации фиксируется отдельно в PROJECT_CONTEXT.md.

## Где менять оформление

| Файл | Что задаёт |
| --- | --- |
| `dist/theme.css` | Единственный словарь значений: семейство и насыщенность шрифта, кегли, адаптивные заголовки, цвета, поверхности, линии, скругления и фокус |
| `dist/typography.css` | Все правила текста: соответствие существующих классов и HTML-элементов токенам, межстрочные/межбуквенные интервалы, мобильные варианты, `@font-face` |
| `dist/style.css` | Общая вёрстка, главная, формы, документы, подвал, cookie-уведомление |
| `dist/navigation.css` | Общая шапка и мобильное меню каталога/блога |
| `dist/catalog.css` | Вёрстка каталога, карточек, галереи, размеров и диалога |
| `dist/blog.css` | Вёрстка списка статей и материала |

Порядок подключения: `theme.css` → `typography.css` → `style.css` → нужные компоненты. Для блога достаточно `navigation.css` и `blog.css`; большой файл оформления товаров ему больше не нужен. Стили и HTML остаются статическими, сборщика и зависимости от JavaScript для чтения нет.

Существующие классы сохранены: менять HTML каждой страницы для общей правки не требуется. Размеры, насыщенность, межстрочные интервалы и ширины текстовых элементов главной, каталога и блога сравнены с исходной версией в Chrome при 390 и 1440 px — совпадают. В каталоге изменён только семантический тип хлебных крошек: `div` → `nav`.

## Шрифт

Manrope, запасные — Arial и системный sans-serif. `--font-body` применяется к body; заголовки, абзацы, ссылки, поля и кнопки наследуют семейство. Оба файла WOFF2 размещены на собственном домене:

- `fonts/manrope-cyrillic.woff2` — кириллица;
- `fonts/manrope-latin.woff2` — латиница, цифры и базовые знаки.

Существующий `em` отображается прямым начертанием: акцент задаётся цветом/фоном, а не курсивом. Логотип — отдельный SVG, смена шрифта страницы его не меняет.

Это вариативный Manrope из Google Fonts v20, диапазон 400–800, `font-display: swap`. Суммарно 39 120 байт. Разделение по `unicode-range` позволяет браузеру запрашивать нужные символы. Редкие знаки вне этих диапазонов используют запасной шрифт. Лицензия SIL Open Font License сохранена в `dist/fonts/OFL.txt`. Внешний Google Fonts `@import` удалён.

| Токен | Насыщенность | Применение |
| --- | --- | --- |
| `--weight-regular` | 400 | Основной текст |
| `--weight-medium` | 500 | Вторичные числовые подписи, заголовки таблиц |
| `--weight-semibold` | 600 | Навигация, выбор размера, вопросы товара |
| `--weight-bold` | 700 | H3, strong/b, текстовые ссылки, подписи |
| `--weight-heavy` | 800 | H1/H2, основные кнопки, крупные цифры, акцентные метки |

При замене семейства меняйте `--font-body` и определения `@font-face`, добавьте локальные файлы с лицензией и проверьте кириллицу, цифры, ×, №, стрелки. Не заменяйте шрифт только в одной карточке. Другой шрифт меняет ширину строк: повторная проверка адаптива обязательна.

## Семантика и общие классы

Сначала выбирайте смысловой HTML-тег: один H1 на страницу, H2 для раздела, H3 для подраздела, `p` для абзаца, `ul/ol` для списка, `strong` для смыслового выделения. Размер текста сам по себе не делает абзац заголовком. Не пропускайте уровни ради внешнего вида.

| Роль / существующие селекторы | Общий класс для нового блока | Правило |
| --- | --- | --- |
| Крупный первый экран `h1`, `.hero h1` | `.type-display` | 64–104 px; главная на мобильном 56–72 px, 800, line-height 1.01, tracking −0.075em |
| Заголовок статьи `.blog-article h1` | `.type-h1` | 36–64 px, 800, 1.13, −0.045em |
| Раздел `h2` | `.type-h2` | 34–56 px, 800, 1.15, −0.05em; на главной до 700 px — 36 px |
| Подраздел/карточка `.product h3`, `.scenario h3` | `.type-h3` | 20 px, 700, 1.3, −0.035em; у существующих блоков сохранены свои адаптивные варианты |
| Основной текст `body`, `.intro` | `.type-body` | 16 px, 1.65 |
| Вводный абзац | `.type-lead` | 18 px, 1.75; статья — 18 px / 1.85, до 800 px — 16 px |
| Описание карточки, подпись управления | `.type-small` | 14 px, 1.65 |
| Второстепенная подпись | `.type-caption` | 12 px, 1.6 |
| Подпись/навигация | `.type-label` | 14 px, 700 |
| Верхняя рубрика/номер раздела | `.eyebrow` | 12 px, 800, расширенный tracking; прежние варианты по разделам — в typography.css |
| Вторичный текст | `.text-muted` | Цвет `--muted` |
| Цветовой акцент | `.text-accent`, `.title-dot`, `.accent-word` | Цвет `--accent` |

Классы `.type-*` нужны, когда смысловой тег и визуальная роль различаются. Для обычных H1/H2/абзацев используйте существующую семантику без дополнительных классов. Не накладывайте общий класс на компонент с более специфическим правилом вроде `.detail-copy h1`: меняйте токен этого компонента. Отступы в общих текстовых классах не задаются — они принадлежат композиции блока.

Слоганы, название компании, почта `info@neesha.ru` и товарные сведения сохранены. В юридических документах отдельные уже существовавшие названия разделов стали H2 с прежним внешним видом; редакция документов не менялась.

## Размеры и адаптив

Размеры выражены через rem; 1rem соответствует 16 px при стандартной настройке браузера. `line-height` без единиц масштабируется вместе с текстом. Fluid-заголовки используют `clamp(min-rem, vw, max-rem)`. Не фиксируйте корневой размер в пикселях и не запрещайте масштабирование viewport.

Сохраняются прежние диапазоны: главная — 700/1000/1600 px, каталог — 540/800/1150 px, блог — 800 px, уведомление — 500 px. Разные заголовки имеют отдельные роли, поскольку главная, статья, карточка и юридический документ решают разные задачи. Унификация означает общий источник правил, а не одинаковый кегль у всех заголовков.

В старом интерфейсе есть подписи 10–13 px. Они сохранены, чтобы не менять согласованную композицию. Для нового основного текста используйте 16 px и выше, для регулярных подписей/управления — 14 px и выше; 12–13 px оставляйте только второстепенным данным. Не используйте старые 10–11 px как образец для новых форм.

Основные общие интервалы: `--line-body:1.65`, `--line-heading:1.15`, `--tracking-heading:-.05em`. Контекстные значения — централизованно в typography.css: статья 1.85, документы 1.8, FAQ 1.55/1.8, основной дисплей 1.01. Не добавляйте новые font-size/font-weight/line-height в файлы вёрстки.

На тёмных крупных заголовках акцент остаётся белым с красным подчёркиванием. Для обычного красного текста не используйте тёмный фон: сочетание должно сохранять читаемость. Не передавайте ошибку/выбор одним цветом — сохраняйте текст и состояния `aria-*`.

## Как внести общую правку

1. Семейство/насыщенность/цвет/базовый кегль/форма — изменить соответствующий токен в theme.css. Например, `--text-small` изменит все привязанные подписи и мелкий текст, `--accent` — все CSS-акценты, `--heading-article` — заголовки статей.
2. Если нужно изменить смысловую роль целиком, изменить группу селекторов в typography.css, включая её media-правила. Не добавлять локальные переопределения поверх старых.
3. Новую статью/товар менять через данные и шаблоны, затем перегенерировать страницы. Не редактировать `dist/blog/` и `dist/catalog/` вручную.
4. Обновить версию URL изменённого CSS во всех исходных HTML/шаблонах. Пять исходных мест: главная, два документа, `blog/base.html`, `catalog/templates/base.html`.
5. Выполнить генерацию и проверки из ops/README.md. Просмотреть 360/390/768/1024/1440 px, крупный текст, меню, формы, длинные подписи и ошибки; проверить клавиатуру, отсутствие переполнения и загрузку кириллицы.
