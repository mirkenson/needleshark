# Сводки Метрики в Loop

Согласовано владельцем 24.09.2026: только Метрика, тот же канал Loop, что и заявки. Ежедневно в 10:00 МСК — вчерашний день (сравнение с тем же днём предыдущей недели); по понедельникам в 10:00 — завершившаяся неделя понедельник–воскресенье; 1-го числа в 10:00 — завершившийся календарный месяц в сравнении с предыдущим полным месяцем. В совпадающие даты это отдельные сообщения. Директ и внеплановые уведомления о показателях не подключены.

## Данные и смысл показателей

`server/metrika_reports.py` обращается только GET к API отчётов счётчика 112428810, с `accuracy=full`, часовым поясом `+03:00` и атрибуцией последнего перехода. Токен создан с единственным правом `metrika:read`; OAuth разрешает читать доступные аккаунту счётчики, но код использует только указанный счётчик сайта. Доступ к Директу, БД заявок, клиентским полям и файлам этому процессу не нужен.

Сводка: пользователи/визиты/просмотры, источники, до трёх известных публичных страниц входа, достижения `lead_submitted`, визиты с этой целью и их доля во всех визитах. Начало формы/попытка отправки показаны как число визитов с соответствующей целью; фокус поля не доказывает заполнение. Недельный и месячный отчёты также показывают визиты с кликом по контактам и CTA блога, отказы и время. Месячный — среднее число визитов в день, чтобы учитывать разную длину месяцев. Изменение конверсии выражается в процентных пунктах. Нулевая база не превращается в бесконечный процент роста; отсутствие визитов — не нулевая конверсия.

Фильтр исключает `isRobot=Yes`, текущие UTM source `qa`, `release_check`, `metrika_check` и medium `qa`, `test`. Не меняет настройки счётчика. Непомеченные проверки могут оставаться. API посещений не равен числу строк в PostgreSQL; цель — событие после серверного сохранения, а не оплаченный заказ. Квалификация, выручка, Ozon-продажи, стоимость заявки и сквозная атрибуция не рассчитываются.

Сравнение с периодом, начинающимся ранее 14.09.2026, обозначается неполным: приём данных после смены домена исправлен 13 сентября. Предыдущие записанные значения показываются, процентный рост по такой базе подавляется. В небольших выборках Метрика может скрывать страницы входа; это явно отмечается. Самплированные, неполные, некорректные ответы и лаг, затрагивающий последний день периода, откладывают отправку; ошибка не заменяется нулями.

Наблюдение формируется детерминированно по агрегатам, с оговоркой о малой выборке, без отправки данных внешней модели. В сообщения не попадают параметры URL, пользовательские названия источников, поисковые запросы, контакты и тексты форм. `server/metrika_pages.json` — разрешённые пути из текущего публичного sitemap; при появлении новых страниц список обновляется отдельным проверенным выпуском отчётчика. Неизвестные пути не отправляются.

## Установка и состояние

Отдельный выпуск `/opt/needle-metrika/releases/<release>`, атомарный `current` и (после следующего выпуска) `previous`. Сайт, обработчик заявок, Nginx и БД не переустанавливаются. Общий HTTP-транспорт `loop_delivery.send_payload` скопирован в выпуск отчётчика; действующий backend продолжает использовать свой проверенный модуль.

`bash ops/install-metrika.sh PRIVATE_METRIKA_ENV` требует чистый код, сохранённый и отправленный upstream коммит. Входной закрытый файл содержит только `METRIKA_TOKEN`. До смены конфигурации инсталлятор проверяет хеши, настоящий API, синтаксис Python и systemd, сохраняет фактические units/ссылки/config в `/opt/needle-metrika/backups/<release>`. Новый `/etc/needle-shark/metrika.env` (root, 0600) содержит токен и копию существующего `LOOP_LEADS_WEBHOOK_URL`, без почты/БД. Изменение исходного webhook позже требует обновления этой закрытой копии.

`needle-metrika.service` — oneshot с DynamicUser, ограничением памяти 96 MiB и закрытым StateDirectory. Таймер проверяет расписание каждые 30 минут: обычная отправка в 10:00 МСК, ошибки повторяются в ближайший получасовой запуск. При первой активации исторические сводки не рассылаются. После простоя догоняется только последняя наступившая сводка каждого вида, чтобы не создавать поток старых сообщений.

`/var/lib/needle-metrika/state.json` содержит время активации и ключи подтверждённо отправленных периодов, без токена/показателей. Блокировка предотвращает параллельную обработку. Успех записывается атомарно с fsync только после HTTP 200/`ok` от Loop; повторный запуск пропускает эти периоды. Потеря подтверждения после принятия сообщения может вызвать дубликат с тем же ключом: exactly-once для webhook не обещается. HTTP-подтверждение не заменяет проверку отображения в канале.

`metrika_reports.py check` читает данные без отправки; `preview --kind daily|weekly|monthly --output PRIVATE_PATH` сохраняет текст с правами 0600. Не включать превью или реальные агрегаты в публичный Git. `run` отправляет только наступившие периоды. Ошибки журналируются нейтральными кодами; автоматические сообщения об ошибках в канал не добавлены.

Отключить расписание: `systemctl disable --now needle-metrika.timer`; дождаться/остановить текущую `needle-metrika.service` при необходимости. Откат: проверить `current`/`previous`, остановить таймер и службу, восстановить проверенные ссылки и units/config из закрытой резервной копии, `systemctl daemon-reload`, затем возобновить прежнее состояние таймера. Не откатывать историю отправок и БД заявок. Первый выпуск не имеет previous; его можно отключить без изменения сайта.
