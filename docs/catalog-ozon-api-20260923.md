## Результат

Через существующий VPS выполнены только запросы чтения к официальному Ozon Seller API. Из 230 записей кабинета сопоставлены все **77 вариантов 26 товаров**, представленных на сайте. Для 23 новых товаров добавлены 62 ссылки; восемь прежних ссылок мотоциклетных и колёсных чехлов подтверждены. Для квадроцикла вместо одной ссылки на все размеры настроены **семь отдельных карточек Ozon**.

Кнопка «Перейти на Ozon» меняет адрес вместе с выбранным размером, цветом или комплектом. Рядом указано, что розничная цена, наличие и доставка проверяются на Ozon. Расчёт партии остаётся основным B2B-действием. У всех исходящих ссылок ровно одна кампания `vendor_org_211216`.

## Как подтверждены ссылки

Для новых вариантов использовано точное совпадение артикула сайта с `offer_id`. Старые восемь ссылок сверены по SKU. Семь размеров квадроцикла сопоставлены с полным полем размеров и артикулом. Во всех 77 случаях SKU согласован между списком, карточкой и атрибутами API; внутренний идентификатор товара также совпадает. Товары не архивированы, создание завершено, модерация одобрена. Адрес формируется из подтверждённого SKU, а не из похожего штрихкода.

Методы: `/v3/product/list`, `/v3/product/info/list`, `/v4/product/info/attributes`, `/v1/description-category/attribute`. Последний метод использован для 23 словарей категорий/типов, чтобы прочитать названия характеристик. Эти POST-запросы только читают данные; карточки, цены и остатки Ozon не менялись.

На момент снимка API 65 вариантов имеют статус «Продается», 12 — «Готов к продаже» с пояснением «Нет на складе». Это временное состояние, а не обещание текущей доступности. Статические цена и наличие на сайте не добавлены.

Публичная витрина Ozon из проверочного браузера не открылась: `ERR_CONNECTION_TIMED_OUT`. Поэтому подтверждено соответствие SKU и адресов данным Seller API, но не успешное открытие всех 77 карточек покупателем и не доступность доставки в конкретный регион.

## Характеристики и расхождения

- **NS-BAG-35-4: четыре сумки.** Владелец подтвердил 23 сентября: «4 сумки — ошибка в названии Ozon». В прототипе комплектность сохранена как 4, ссылка ведёт на SKU 5620727222. Заголовок Ozon «набор 2 шт.» этой задачей не исправлялся.
- **ATV-110-2:** полные размеры в названии/атрибуте — 256 × 110 × 120 см; отдельная высота в API ошибочно указана как 1202 см. Подтверждённый размер сайта не заменён.
- У сумок 35 и 108 л встречаются одинаковые габариты 45 × 30 × 80 см; это не основание публиковать их как проверенные размеры 35-литровой сумки.
- У сумок 237 л расходятся 210D в названии и 600D в описании. Плотность не импортирована.
- Масса накидки на бампер 130 г против 100 г с упаковкой противоречива; в покупательские характеристики не перенесена.
- Габариты верхнего уровня ответа API относятся к упаковке. Общие поля совместимости не доказывают посадку чехла на конкретную модель техники.

Именованные дополнительные атрибуты, названия, статусы и сопоставления сохранены в [обезличенном JSON-отчёте](verification/20260923-ozon-api-mapping.json). Они служат материалом для проверки, а не автоматически одобренным текстом сайта. Из API в покупательский каталог перенесены подтверждённые адреса; исходные спорные характеристики не заменены.

## Хранение каталога

Источник сайта остаётся `catalog/products.json`; общий `catalog/render.py` генерирует статические страницы. Ссылки обычных вариантов находятся в `variants[].ozonUrl`, происхождение — в `variants[].source.ozon`. Для прежней модели размеров квадроцикла добавлено `sizeOzonUrls`; перенос архитектуры не требуется. Служебные сведения источника не экспортируются в публичный JSON вариантов.

Для 26 товаров и 77 вариантов отдельная товарная БД сейчас не обязательна. БД и серверная синхронизация понадобятся при редактировании через админку несколькими сотрудниками, регулярном обновлении цен/остатков, собственном оформлении заказов или интеграции с учётом. Действующая PostgreSQL хранит заявки, а не каталог. Разовая сверка API не означает подключённую постоянную синхронизацию.

Ключ прочитан из предоставленного владельцем файла, передан на собственный VPS через зашифрованный SSH stdin и использован в памяти для запросов к официальному API. В команды, HTML, Git и отчёт ключ не включён; постоянный файл с ним на VPS не создавался. Полные приватные ответы API остаются вне репозитория.
