# Контекст сайта в Git и Obsidian

По поручению владельца от 22 сентября 2026 года информацию о сайте сохраняем в двух местах:

- Git: `docs/PROJECT_CONTEXT.md`, документация разделов и обезличенные отчёты.
- Obsidian: проект `/Users/mirkenson/Documents/Sazonov BD/1 ПРОЕКТЫ/Needle Shark`, снимок контекста `Сайт/Материалы из Git/docs/PROJECT_CONTEXT.md`.

Вход в проект — `00 Needle Shark.md`, вход в материалы сайта — `Сайт/00 Сайт.md`. Существующие бизнес-заметки владельца остаются в прежних папках; карты разделов и явные ссылки связывают их с сайтом. Их содержание не переносится в Git автоматически.

## Обновление после каждой существенной задачи

1. Прочитать Git-контекст и проверить состояние зеркала: `python3 ops/sync-obsidian.py --check`. Если зеркало меняли вручную, прочитать diff и перенести относящиеся к сайту уточнения в соответствующие исходники Git, сохраняя авторские заметки. Не затирать конфликтующие изменения.
2. Обновить `docs/PROJECT_CONTEXT.md`, затронутые инструкции и отчёт. Различать написанный код, установленный релиз, реально выполненные проверки и отложенные задачи.
3. Проверить diff и сохранить согласованные изменения в коммит. Скрипт читает **HEAD**, а не незакоммиченные файлы. Чужие неотслеживаемые файлы, включая `outputs/`, не захватываются.
4. Из корня репозитория выполнить `python3 ops/sync-obsidian.py`, затем `python3 ops/sync-obsidian.py --check`. При недоступном vault явно сообщить, что обновлён только Git; не объявлять обе копии актуальными.
5. Отправить проверенный коммит в GitHub. В итоговом сообщении указать результат обновления обеих копий и статус публикации сайта. После нового коммита повторить синхронизацию, включая финальную документацию.

Это обязательный шаг завершения работы с проектом, а не фоновый процесс: таймер, Git hook и внешняя автоматизация не установлены. На другой машине можно передать `--project '/полный/путь/Needle Shark'`.

## Что переносится

`ops/sync-obsidian.py` использует только стандартную библиотеку Python и Git. В `Сайт/Материалы из Git/` копируется полный набор файлов выбранного HEAD с исходной структурой и байтами: все Markdown, JSON, SQL, исходники, шаблоны, тесты, конфигурационные примеры, публичные страницы, изображения и шрифты. Относительные ссылки внутри копии документации сохраняются. Контекст в Git и в зеркале побайтово одинаков.

Дополнительно создаются индекс всех файлов, история сообщений коммитов, читаемые Markdown-копии JSON-отчётов, данных каталога и статей. Они формируются автоматически; источники данных редактируют в Git. История `.git`, другие ветки, серверная база, заявки, секреты, игнорируемые и незакоммиченные файлы не экспортируются. Скрытые `.openai`/`.gitignore` копируются, но Obsidian может не показывать их в дереве.

`Сайт/Синхронизация Git.json` содержит коммит, число и объём исходников, SHA-256 каждого управляемого файла. `--check` читает их без записи. Повторный запуск без изменений не переписывает файлы. Скрипт заранее проверяет конфликты и прекращает весь запуск, если существующий файл отличается и от прошлого снимка, и от новой версии Git. Символические ссылки в целевых путях отклоняются. Исчезнувшие из Git файлы сохраняются в Obsidian как архивные и перечисляются в `retired`; массового удаления нет.

Перенос не перепроверяет работоспособность VPS или фактическую доставку писем. Даты и ограничения прежних отчётов сохраняют своё значение. Материалы, генерации изображений и бизнес-исследования не становятся подтверждёнными фактами от самого копирования.

## Проверка инструмента

```sh
python3 -m unittest discover -s ops -p 'test_obsidian_sync.py'
python3 ops/sync-obsidian.py --check
```

Тесты используют временные Git-репозитории и временные папки, без доступа к реальному хранилищу Obsidian или серверу. Проверяют полноту снимка и исключение незакоммиченных материалов, повторяемость, отказ при конфликте без частичной записи, обновление после коммита, сохранение удалённого в Git файла и защиту от символических ссылок.
