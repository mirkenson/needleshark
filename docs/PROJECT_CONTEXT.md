# Технический контекст Needle Shark

Обновлено: 9 сентября 2026 года. Это снимок подтверждённого состояния, а не замена проверке сервера.

## Цель и продукт

Сайт швейного производства технических изделий в Санкт-Петербурге. Основной сайт: https://needleshark.ru/ (также www). Брендовый цвет `#BE3E3E`, логотип `dist/logo.svg`. Главная: первый экран, о производстве, контроль этапов, продукция, доверие/маркетплейс, B2B, заявка, подвал. Сохранять согласованный дизайн и улучшать его итерационно.

Магазин: https://www.ozon.ru/seller/needle-shark/. Владелец сообщил 80 тысяч+ продаж, рейтинг 4.9 и 24 тысячи отзывов. Независимая проверка этих цифр не выполнена. Вымышленные цитаты покупателей не опубликованы. Изображения чехла квадроцикла, органайзера и рулонов ткани сгенерированы. Почта заявок: `info@neesha.ru`.

## Код и публикация

- Репозиторий: https://github.com/mirkenson/needleshark, основная ветка `main`.
- `dist/` — исходные публичные HTML/CSS/JS и изображения, а не одноразовый результат сборки. Сборщик не требуется.
- Локальный просмотр: `python3 -m http.server 4173 --directory dist`.
- `ops/deploy.sh` — загрузка статических файлов на VPS через `needledeploy`, новый релиз и атомарная смена ссылки.
- `ops/needle-shark.nginx.conf` — сохранённая конфигурация; перед изменением сравнить с сервером.
- `server/` — подготовленный Python обработчик, очередь SQLite, systemd unit, тесты и будущий JS формы.
- `google/Code.gs` — исходник Google Apps Script. Текущая версия в Google использует фиксированный ID таблицы и проверяет заголовки без изменения оформления; перед обновлением сверить различия.
- `.openai/hosting.json` относится к старому отдельному прототипу https://needle-shark-prototype.mirkenson.chatgpt.site/. Основной VPS через Sites не публикуется.

## Инфраструктура

VPS Rucloud: `194.87.99.98`, Ubuntu 24.04, тариф 0.5 ГБ RAM / 10 ГБ SSD, swap 1 ГБ. Nginx, firewall с портами 22/80/443. DNS домена управляется в reg.ru.

Документ root: `/var/www/needle-shark/current`; релизы: `/var/www/needle-shark/releases/`; `previous` хранит предыдущий релиз. Nginx: `/etc/nginx/sites-available/needle-shark`. Let's Encrypt обслуживает оба домена, продление через certbot.timer; актуальное состояние сертификата проверять на сервере. Индексация пока ограничена заголовком `noindex, nofollow`; не снимать автоматически.

SSH: `~/.ssh/needle_shark_ed25519`, пользователи `needledeploy` для релизов и `root` для администрирования. GitHub использует отдельный ключ `~/.ssh/needle_shark_github_ed25519`. Здесь указаны только пути, не секреты. На другой машине требуется настроить доступ заново.

Владелец явно разрешил публичный доступ к endpoint с проверкой секретного ключа. Он установил `SHARED_SECRET` в свойствах скрипта. Локальный секрет находится в игнорируемом `server/google-shared.key`; не читать его в вывод и не добавлять в Git.

9 сентября прямой тестовый POST к webhook вернул `ok:true` с соответствующим ID. По логике обработчика это подтверждает завершение записи в таблицу и вызова отправки письма. Фактическое получение во входящие отдельно не подтверждено. Это был тест Google напрямую, не тест формы сайта.

**Форма на публичном сайте всё ещё отключена. Установка Python-службы на VPS и сквозной тест ещё не выполнены. Не считать интеграцию завершённой.**

Подготовленная архитектура: POST `/api/leads` → локальная долговечная очередь SQLite → Google Sheets + письмо. Секрет хранится только на сервере и в Apps Script. Повторы дедуплицируются по UUID. Вложения JPG/PNG/PDF до 2 МБ идут в письме; в таблице только имя файла. При сбоях Google очередь повторяет отправку. Письмо может повториться при сбое между отправкой и отметкой результата. Доставленные локальные данные очищаются через 7 дней; необработанные остаются для повторной попытки. Это описание кода, пока не подтверждённой установки.

## Следующие работы по интеграции

1. Сверить реальный сервер и исходники; выполнить `python3 -m unittest discover -s server -p 'test_*.py'`.
2. Установить Python-службу по `server/README.md`, секрет и URL в root-owned `/etc/needle-shark/leads.env` с правами 0600.
3. Добавить точный Nginx route `/api/leads` на localhost:8091 с лимитами и переопределением `X-Real-IP`. Порт наружу не открывать.
4. Выполнить сквозной помеченный тест через VPS, проверить запись, подтверждение отправки письма, повторы и ошибки.
5. Только после этого активировать форму: подключить подготовленный JS, ограничения файлов и honeypot, убрать сообщение о недоступности.
6. Сохранить проверенную версию в GitHub, опубликовать релиз, проверить HTTPS, адаптивы и реальную форму. Обновить эту запись.

## Особенности локальной среды Codex

На текущем Mac системный git может требовать Xcode. Рабочий git найден в `/Users/mirkenson/.cache/codex-runtimes/codex-primary-runtime/dependencies/bin/fallback/git`. Это особенность этой машины; не вшивать путь в проектные скрипты. Сетевые вызовы из песочницы могут требовать разрешённого расширения доступа; ошибка DNS в песочнице не доказывает неисправность Google или VPS.
