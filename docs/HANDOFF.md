# Работа с Needle Shark на другой машине

Сверка GitHub: 18 сентября 2026 года. Основная ветка репозитория — `main`. До этой синхронизации её HEAD был `239761f`; актуальные материалы хранились в рабочих ветках. Синхронизация переносит документацию, а не объединяет весь код этих веток.

## Порядок чтения

1. `AGENTS.md` — ограничения и порядок работы.
2. `docs/PROJECT_CONTEXT.md` — история, подтверждённые публикации и незавершённые этапы. Более поздняя запись может уточнять старую; наличие файла или коммита не означает установку на сервер.
3. Инструкция затрагиваемой части: `ops/README.md`, `server/README.md`, `catalog/README.md` или `business/README.md`. Для любой статьи обязательны **оба** файла: `blog/README.md` и `blog/ARTICLE_GUIDE.md`.
4. `docs/ANALYTICS.md`, `docs/TYPOGRAPHY.md`, `docs/SEO.md` — по предмету изменения. Отчёты в `docs/verification/` содержат ограничения выполненных проверок.

## Выбор исходной версии кода

Сначала выполните `git fetch origin` и проверьте состояние нужной ветки. Следующие коммиты — проверенные ориентиры на момент синхронизации, а не обещание неизменности веток.

| Опубликованный блог, каталог и общий сайт | `codex/blog-reading` | Код релиза `6fe6a17`; отчёт публикации и документация `dfd7963`. Статический релиз `20260914T085850Z-10644` |
| Установленный редирект `neesha.ru` / `www.neesha.ru` | `codex/neesha-redirect` | Конфигурация `0a89b9e`, проверка установки `90af4f6`. Основана на `dfd7963`; статический релиз не менялся |
| Незавершённая B2B-страница, новые поля заявок и файлы Drive | `codex/business-prototype` | Снимок документации `a353fc6`. Установка backend/Google и сквозная проверка ещё не подтверждены этой записью; читать последние коммиты и контекст ветки |
| Общие инструкции для первого знакомства | `main` | Актуальная документация; код приложения в этой синхронизации не обновлён |

Для правки опубликованной статьи создайте свою ветку `codex/<название-задачи>` от актуального `origin/codex/blog-reading` либо отдельную рабочую копию от этой версии. Отредактируйте данные в `blog/posts.json`, используйте общий `blog/blocks.py` и генератор `blog/render.py`. Не создавайте отдельную разметку вместо общего шаблона.

Если работа касается Nginx, учитывайте изменения в `codex/neesha-redirect` и сначала сравните конфигурацию с VPS: старый файл из другой ветки не содержит всех установленных редиректов. Для продолжения B2B используйте её рабочую ветку и проверяйте последние записи: разрешение на шаг, написанный код и фактическая установка — разные состояния.

## Что переносится отдельно от Git

Для редактирования нужны Git и Python 3; дополнительные инструменты перечислены в инструкциях соответствующего раздела. Абсолютные пути к локальным средам прежнего Mac не обязательны на новой машине. Для публикации необходим отдельно настроенный SSH-доступ к VPS. Для работы с Google нужны разрешённый аккаунт и существующие закрытые свойства Apps Script. Значения ключей, секретов, списков получателей и данные заявок нельзя добавлять в репозиторий.

Локальные предпросмотры и временные артефакты не являются публичным сайтом. `outputs/` не включалась в эту синхронизацию. GitHub не заменяет резервную копию базы заявок.

## Как сохранять актуальность

После существенных изменений обновляйте контекст и инструкцию затронутой части в рабочей ветке. При завершении задачи проверяйте, доступны ли новые правила из `main`: отправка только рабочей ветки не делает их видимыми при обычном клонировании. При синхронизации документации сохраняйте различие между опубликованным кодом и черновиками; не переносите неподтверждённый статус установки. Если HEAD рабочих веток изменился, сверяйте их последние документы перед продолжением.
