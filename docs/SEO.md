# SEO и доступность содержания для поисковых/AI-систем

Обновлено 11 сентября 2026. Изменения опубликованы на основном домене `https://needle-shark.ru/` 11 сентября 2026. Релиз и фактические результаты проверки индексации зафиксированы в PROJECT_CONTEXT.md.

## Единый источник метаданных

`site_utils.prepare_html()` устанавливает canonical и вызывает общий `common_metadata()` для каждой страницы. Он удаляет только принадлежащие ему прежние метатеги и создаёт ровно один набор заново. Повторный запуск не меняет результат. Все новые страницы каталога/блога получают те же правила из общих генераторов.

Для каждой страницы предусмотрены:

- один понятный title и отдельное description на русском языке;
- canonical основного HTTPS-домена без `.html`/`index.html`;
- `index,follow,max-image-preview:large`;
- Open Graph: название, описание, тип, адрес, язык, бренд и существующее изображение;
- Twitter Card с теми же данными;
- общий набор SVG/PNG/ICO-фавиконов, Apple Touch Icon и manifest;
- `Organization`, `WebSite` и `WebPage` с постоянными связанными `@id`.

На главной title конкретизирует пошив чехлов и технических изделий в Санкт-Петербурге. Слоган в первом экране сохранён. В каталоге description описывает реальный способ обращения и больше не обещает доступную покупку на маркетплейсах без товарных ссылок. Юридические документы получили отдельные description; их текст не переписывался. Уже существовавшие самостоятельные названия разделов размечены H2 с прежним внешним видом.

| Страница | Дополнительная структурированная информация |
| --- | --- |
| Главная | Бренд, сайт, компания и Санкт-Петербург, подтверждённый email и VK |
| Каталог | CollectionPage, ItemList только видимых товаров в их фактическом порядке, BreadcrumbList |
| Товар | Product: название, описание, изображения, материал, покрытие, цвет, категория и семь размеров; BreadcrumbList |
| Блог | CollectionPage, ItemList только опубликованных статей, BreadcrumbList |
| Статья | BlogPosting: название, описание, дата публикации, реальная дата изменения при наличии, издатель, ссылки на использованные источники; BreadcrumbList |
| Документы | WebPage с собственными названиями и адресами |

Product описывает изделие, но **пока не соответствует требованиям товарного расширенного результата Google**: нет подтверждённой цены/Offer либо отзыва о конкретном товаре. Цены, остатки, SKU/GTIN, сроки доставки и рейтинг товара не выдумываются. Цифры рейтинга магазина на главной не превращаются в рейтинг чехла. После появления подтверждённых цен нужно отдельно обновить видимый текст, данные и разметку.

У статьи не добавляется вымышленный автор или иллюстрация. Дата изменения заполняется только при содержательной редактуре. Организация связана с существующим логотипом и контактами; полный адрес, телефон и часы работы не заявляются, поскольку не подтверждены.

## Содержание для ответов и агентов

Описания, размеры, характеристики, таблицы, FAQ, статья и источники присутствуют в исходном статическом HTML. Они читаются без выполнения JavaScript. Вопросы товара раскрываются нативным `details`; данные не подгружаются скрытым API. В статье сохранён самостоятельный краткий ответ во введении, смысловые H2/H3, списки и первичные источники рядом с соответствующими советами.

Структурированные данные описывают тот же продукт и содержание, которое видит человек. Нельзя добавлять скрытые ключевые слова, мнимые отзывы, неподтверждённую совместимость или специальные инструкции для LLM. `llms.txt`, метатеги «AI-ready» и специальные схемы сами по себе не являются условием попадания в AI-ответы Google; они не добавлены как обещание индексации. Дополнительные требования конкретных систем стоит проверять по их официальной документации, когда появится конкретная интеграция.

SEO/AEO не гарантирует обход, сроки индексации, позиции или цитирование. Проверка валидности HTML/JSON-LD подтверждает техническую готовность, а не фактическое присутствие в индексе.

## Обход и URL

`ops/prepare-public.py` создаёт robots.txt и sitemap.xml из готовых данных. В карте находятся главная, каталог, товар, блог, опубликованные статьи и два документа. Черновики не входят. `lastmod` добавлен только статье из реального поля `updated`/`date`; дата сборки не выдаётся за дату изменения текста.

В robots.txt публичный сайт разрешён для всех роботов, `/api/` исключён как нетекстовый служебный endpoint. Это правило не заменяет защиту API и не меняет существующие серверные права. Ресурсы, шрифты и фавиконы доступны для обхода. Внутренние ссылки документов и index.html нормализуются с сохранением query/fragment. Внешние ссылки сохраняют ранее согласованные UTM, внутренние не получают UTM.

Три алиаса домена уже перенаправляются на основной на VPS. Новых серверных редиректов в этом этапе не устанавливалось. Адреса с `.html` и `index.html` могут технически отвечать 200, но canonical и внутренние ссылки указывают на основной вариант; это не заявление об обязательном 301 для всех вариантов путей.

## Фавиконы и изображения

Квадратный значок сделан из существующего красного `n` логотипа без новой типографики: favicon.svg, favicon-96.png, favicon.ico (16/32/48), apple-touch-icon.png (180), icon-192.png и icon-512.png. Адреса фавиконов стабильны. `brand-preview.png` — существующий логотип на фирменном фоне для ссылок; новая иллюстрация не генерировалась.

Исходные PNG/JPG сохранены. `ops/optimize-images.py` создаёт WebP-версии шириной 160/480/800/1200/1536 px без увеличения исходника. `ops/image-manifest.json` хранит реальные размеры, SHA-256 оригинала и объёмы. Новый товар автоматически включается по `products.json`; после добавления/замены исходника нужно повторить оптимизацию. Главная использует те же подготовленные файлы; при замене её изображения обновить srcset/preload.

У изображений есть alt, реальные width/height, srcset/sizes. У первого изображения товара и главной высокий приоритет; остальные загружаются по мере приближения к экрану. Галерея меняет и src, и srcset; миниатюры используют 160 px. У исходного чехла на главной исправлены декларации 1536×1024 на фактические 900×1124, при этом его кадрирование сохраняет прежний контейнер 3:2.

## Проверка и последующие действия

Перед выпуском: генераторы → `ops/prepare-public.py` → `ops/check-site.py` и существующие тесты → браузер на пяти ширинах. `check-site.py` проверяет H1, уникальность id, локальные ссылки/якоря/ресурсы, метаданные, JSON-LD, sitemap и CSS-токены. Он не отправляет заявки и не вызывает сторонние системы.

После каждого выпуска проверять HTTPS, ресурсы и заголовки реального сайта; при существенном обновлении отправлять sitemap/важные URL на переобход в Google Search Console и Яндекс Вебмастере из аккаунта владельца. Результаты текущей проверки кабинетов — в PROJECT_CONTEXT.md. На главной сохранены публичные метатеги подтверждения Google и Яндекса: не удалять их при генерации и публикации. Затем оценивать реальные показы, страницы в индексе, ошибки обхода и Core Web Vitals. Результаты Chrome и уменьшение файлов не подменяют полевые метрики.

На VPS текущий `Cache-Control: no-cache` требует ревалидации ресурсов; сжатие текстовых ответов и длительный кеш лучше отдельно настроить после чтения/резервирования живой конфигурации и выбора стратегии версий файлов. В этой задаче Nginx, systemd, API и базы не менялись. Старая задача обновления домена счётчика Метрики остаётся отдельной и не считается выполненной этим аудитом.
